## Modes (one line each)

- monitor: labels requests and signals only; never proposes, never blocks, never activates rules.
- recommend: for suspicious clients compiles rules and runs the benign-replay gate; gate-passing rules are stored PROPOSED with the gate result as evidence (`shield_gate`), gate-rejected rules open an EscalationTicket; NEVER activates and never blocks traffic.
- enforce, auto_shield false: same as recommend (rules stay PROPOSED) until `approve_rule` / `scripts/shield_rules.py approve`, which records an ApprovalRecord, RE-RUNS the gate and activates only if it still passes. Enforce evaluates ACTIVE rules (403 + `X-Sentinel-Shield: blocked`).
- enforce, auto_shield true: rules that pass the gate are activated automatically.
- Activation: `RuleLifecycle.activate_rule(rule_id, gate_result)` is the only code that sets ACTIVE; it raises `GateError` unless the GateResult passed, its rule hash matches and it is under 60 s old. A static test fails if ACTIVE is assigned anywhere else in `packages/shield` or `scripts`.
