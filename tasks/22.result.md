# TASK 22 result — Shield intent accuracy and injection protection

Branch: work/ds | Starting commit: 4b86484 | Final commit: see below

## Summary
Improved deterministic intent classification in the live shield reverse proxy. The previous `map_intent` used first-signal-wins (ignoring all but the first fired signal) and had no EXFIL_ATTEMPT signals, no distinction between rapid vs repeated failed logins, and no aggregated confidence across multiple signals. The fix adds `aggregate_intent()` (confidence-weighted voting across all signals), new signal types (rapid_failed_logins, nosqli_probe, command_injection, directory_traversal, sensitive_admin_path, data_transfer_large, directory_listing), and routes the proxy's intent classification through `aggregate_intent` instead of `map_intent`. All intent labels remain INFERRED (never OBSERVED) and cite real evidence event ids.
