# 11b.result.md — Live Shield Parts 3-6: real three-way run through the proxy

## What was wrong
- `packages/shield/server.py` did not exist, so no proxy could start; arms B and C went direct to the lab.
- The simulator called `GuardedClient.request(json=..., params=...)`, which does not accept those arguments. Every call raised, the exception was turned into a fake 403, and the "65 blocked by lab auth, 0 reached upstream" counters were that artifact. `requests.jsonl` was empty.
- `ShieldProxy._evaluate_rules` was a stub that never blocked, and the benign-replay gate evaluated PROPOSED rules, which never match, so it passed everything.

## What changed
- `packages/shield/server.py` (new): uvicorn factory, env overrides, `/__shield/health|counter|stats` control plane.
- `packages/shield/proxy.py`: real rule evaluation (403 + `X-Sentinel-Shield: blocked`), per-request intent evidence events, auto-shield (compile → benign-replay gate → activate or escalate), forwarded/blocked counters, per-request shield overhead.
- `packages/shield/rules.py`: gate replays the candidate as ACTIVE. `packages/shield/detect.py`: `/api/login` counts as a login path, `notes/<id>` counts as an object path. `packages/shield/benign.py` (new): benign set parsed as data from `labs/vibe_notes_node/benign_traffic.py`.
- `scripts/hacker_sim.py`, `scripts/run_three_way.py`: rewritten (see report). Lab reset + state-hash assertion per arm, proxy as a real subprocess, clean shutdown (no listeners left on 18081/18090).
- `tests/integration/test_shield_proxy.py` (new, 3 tests): monitor blocks 0, enforce blocks with marker, gate rejects a rule that would block benign.
- `opencode.json` untracked from the index (still ignored); `.gitignore` rewritten as UTF-8 text with every entry kept. `pyproject.toml` was missing from the working tree and was restored from HEAD.

## Limitations (see report.md for the full list)
- Intent accuracy (arm C): recon 0.35, failed_logins 0.67, object_enum 0.00, injection 0.38, admin_probe 0.00. Window signals are sticky per client, so after the failed-login stage later requests are labelled CREDENTIAL_GUESSING; object_enum was blocked by per-path `rate_limit_client` rules for the wrong reason.
- `admin_probe` never fires (needs 5 admin hits, the script sends 4); admin routes are labelled RECON.
- Injection is not protected: the benign set also uses `/api/search?q=`, so the gate rejects and escalates the rule.
- 0 benign false blocks is by construction: rules are scoped to the attacker client key.
- One run per arm, one scripted attacker, loopback only.
